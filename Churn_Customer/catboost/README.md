# Churn Customer — ניסויי CatBoost


---
 
##  מטרה
 
חיזוי האם לקוח ינטוש (Churn=1) או יישאר (Churn=0) בפלטפורמת מסחר אלקטרוני,
על בסיס נתוני התנהגות, העדפות ושביעות רצון.
 
---


##  נתונים
 
| פרמטר | ערך |
|-------|-----|
| קובץ | `E Commerce Dataset.xlsx` (Sheet: E Comm) |
| שורות | 5,630 |
| עמודות | 20 |
| משתנה מטרה | `Churn` (1 = נטש, 0 = נשאר) |
| התפלגות | 4,682 נשארו (83.2%) / 948 נטשו (16.8%) |
| חוסר איזון | יחס 4.94:1 לטובת המחלקה השלילית |
 
---


##  אסטרטגיית חלוקת הדאטה
 
**Hold-out 70/30, shuffle=False**
 
הדאטה מחולק פעם אחת לפי סדר השורות המקורי:
 
| חלק | שורות | אחוז | Churn=1 |
|-----|-------|------|---------|
| Train | 3,941 | 70% | 17.2% |
| Test  | 1,689 | 30% | 15.9% |
 
- ה-Test set נחשף למודל **פעם אחת בלבד** — בהערכה הסופית
- `shuffle=False` — 70% הראשונים לאימון, 30% האחרונים לבדיקה
- אין Cross Validation

- מודל CatBoost עם פרמטרים ברירת מחדל

- ללא תיקון חוסר איזון
- סף קלסיפיקציה: 0.50

##  מסקנות ניסוי 1
 
**הצלחה:**
- ROC AUC של 0.9846 — המודל מפריד היטב בין המחלקות
- Precision גבוה (0.9136) — כשהמודל מנבא נטישה הוא צודק ב-91% מהמקרים
- Accuracy כללי גבוה מאוד (95.97%)
**חולשות:**
- Recall של 0.8253 — המודל **מפספס 47 לקוחות נוטשים** מתוך 269 ב-Test
- חוסר האיזון בדאטה (4.94:1) גורם למודל להטות לצד המחלקה הרוב
- מבחינה עסקית: לקוח נוטש שמתפספס עולה יותר מלקוח שמסווג בטעות כנוטש

##  ניסוי 2 — CatBoost עם Class Weights + Threshold Tuning

### גישה

שני שינויים מרכזיים ביחס לניסוי 1:

שני שינויים מרכזיים ביחס לניסוי 1:
 
1. **`auto_class_weights="Balanced"`** — CatBoost מחשב אוטומטית משקל גבוה יותר למחלקת הנוטשים (1) בזמן האימון, כדי לפצות על חוסר האיזון

##  מסקנות

- הוספת `auto_class_weights="Balanced"` שיפרה את ה-Recall מ-82.5% ל-92.6% (threshold=0.50), ללא צורך בשינוי הדאטה
- ה-ROC AUC עלה מ-0.9846 ל-0.9860 — המודל השתפר גם ברמת הדירוג הכללי
- **Threshold = 0.50** מהווה את נקודת האיזון הטובה ביותר בניסוי 2: Recall של 92.6% תוך שמירה על F1 גבוה ו-20 נוטשים בלבד שמתפספסים (לעומת 47 בניסוי 1)
- **Threshold = 0.30** מתאים כשהעדיפות העסקית היא לתפוס כמה שיותר נוטשים — Recall של 94.8%, אך על חשבון יותר False Positives (115 לקוחות שמסווגים בטעות כנוטשים)
- הפחתת ה-False Negatives מ-47 ל-20 (threshold=0.50) מייצגת שיפור של **57%** בתפיסת לקוחות נוטשים
- החלוקה hold-out 70/30 ללא shuffle מבטיחה שה-Test set נחשף **פעם אחת בלבד**, ומונעת data leakage
